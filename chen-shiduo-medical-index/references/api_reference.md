# 小程序与后端接入

## 运行边界

WorkBuddy Skill 不能直接作为微信小程序运行。患者端应调用医院审核后的后端服务。后端可以读取 `dist/index.json`，也可以复用 `scripts/index_core.py` 的确定性检索逻辑。

## 本地演示

```bash
python scripts/build_index.py
python scripts/server.py --host 127.0.0.1 --port 8000
```

健康检查：

```text
GET /health
```

检索接口：

```text
GET /v1/navigation/search?q=头痛
```

返回状态包括：

- `ok`：存在已核对索引，返回出处和通用导航。
- `no_match`：没有可靠匹配，不生成推测结果。
- `emergency`：命中急症拦截，只返回急诊提示。

演示服务默认只绑定 `127.0.0.1`，不记录完整查询路径。它不是生产分诊服务，未提供医院所需的身份认证、审计、限流、高可用和安全评审能力。

## 微信端示例

`examples/miniprogram.js` 展示 `wx.request` 调用方式。接入时须完成：

1. 将域名替换为医院正式 HTTPS 域名，并配置微信小程序 request 合法域名。
2. 由后端校验查询长度、请求频率和响应内容，不在前端存放密钥。
3. 对 `emergency` 使用全屏或显著提示，提供拨打 120 和联系医院人工服务入口。
4. 对 `no_match` 提供人工预检分诊入口，不自动补写答案。
5. 只收集实现功能所需的最少信息，提供隐私政策，不在日志中保存原始症状文本。
6. 在正式发布前完成医院审核、微信类目与合规核查以及真实环境测试。

## 静态索引方式

低流量且无需频繁更新时，可由医院后端下发经过审核的 `dist/index.json`。不建议把完整检索和急症规则仅放在客户端，因为规则更新、版本回滚、审计和紧急下线都需要服务端控制。
